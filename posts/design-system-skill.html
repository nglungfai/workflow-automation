Turn a Drive Folder into a Cowork Skill: Auto-Applying a Design System

Skill Deep Dive · 5 min read

This site just got re-themed with a real company design system: Poppins type, aubergine and teal action colors, pill buttons, 20px card radii. It replaced a generic dark theme.

The re-theme isn't the interesting part. Making it automatic for every future HTML task is.

If your team ships internal tools, decks, or prototypes and wants them on-brand without re-explaining the brand every time, this is the pattern to copy.

A design system in Drive doesn't help until something reads it

Our company already had a real design system. colors_and_type.css held every color, type, radius, and shadow token. There were logo SVGs and a Figma-sourced brand guide. All of it lived in a "Design System" folder in Google Drive.

That's useful only if whoever's building something remembers the folder exists, finds it, and copies the right values by hand. It doesn't scale past one person.

Packaging it as a Cowork skill

A Cowork skill is a folder with a SKILL.md manifest plus supporting files, zipped with a .skill extension. Once it's installed via Settings → Capabilities → Skills, Cowork matches the skill's description against your requests and pulls it in automatically. Nobody has to say "use the design system."

Our Drive folder already had a SKILL.md written for exactly this purpose. It just hadn't been packaged or installed.

What we did, step by step

  1. Located the source folder. Searched Google Drive and found SKILL.md, README.md, colors_and_type.css, plus an assets/ folder with logo SVGs and bundled Poppins font files.
  2. Pulled exact file contents. This is the step that's easy to get wrong. A file's "natural language representation", what a casual content preview returns, mangles code syntax: quotes get escaped and symbols become entities. Anything that has to run as real CSS or markdown needs the exact bytes, so download the raw file and decode it. Don't summarize it.
  3. Assembled the skill folder. SKILL.md, README.md, and colors_and_type.css copied byte-for-byte, plus the 6 logo SVGs under assets/.
  4. Zipped it with the right structure. The zip needs the skill's folder (matching the name: field in the SKILL.md frontmatter) with SKILL.md inside it. Not a flat dump of files, and not the folder's contents zipped without the wrapping folder.
  5. Installed it. Uploaded the .skill file via Settings → Capabilities → Skills. From then on, any request that looks like building a branded interface, mock, deck, or prototype triggers the skill automatically.

What we deliberately left out

The full Drive folder also has about 30 HTML preview cards, each component rendered standalone, and a full React reconstruction of our data platform's UI under ui_kits/platform/. Those stayed in Drive for two reasons: package size and relevance.

The core token file plus logos covers most "make this on-brand" requests: plain HTML pages, decks, one-off mocks. The UI kit serves a narrower case, recreating the actual platform app, and it's still one Drive search away.

We also left out the 8 bundled Poppins .ttf files. Binary assets are impractical to move through a text-based packaging pipeline. colors_and_type.css still references them through local @font-face rules. If they're absent, add a Google Fonts fallback link to the page <head> before the stylesheet:

<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Poppins:ital,wght@0,400;0,500;0,600;0,700;1,400&display=swap">

A discrepancy we caught along the way

README.md and colors_and_type.css disagree on the primary action color. The README describes royal purple #590094 as primary with turquoise #00CBB2 as secondary. The CSS file, which labels itself "source of truth", defines deep aubergine #3F2A7B as primary and muted teal #3D7D7B as secondary.

We used the CSS values everywhere on this site, since that's what actually renders. Whoever owns the design system should reconcile the two documents, so the next person pulling from Drive doesn't get conflicting guidance.

Try it yourself

The design-system skill is installed and available. If you're building an internal tool, a one-off HTML mock, or a deck and want it on-brand without hand-copying hex codes:

  • Just ask Cowork to build it. Mentioning the brand name or "branded" is usually enough to trigger the skill.
  • Link colors_and_type.css in your page <head> and use its CSS variables (var(--action-primary), var(--radius-pill), etc.) instead of hardcoding hex values. That keeps everything consistent if the tokens ever change.
  • Reach for the existing utility classes (.pdp-btn--primary, .pdp-chip--succeeded, .pdp-card) before rolling your own.

Where this breaks

Two documents disagree. The skill follows the CSS, but anyone who reads the README still gets a different primary color until someone reconciles them.

The installed skill is a copy. It was zipped from the Drive folder at one point in time, so the Drive version and the installed one can drift apart.

The fonts aren't bundled. Without the .ttf files, the @font-face rules point at nothing, and pages rely on the Google Fonts fallback link.

Triggering rides on the description. Mentioning the brand or "branded" usually pulls the skill in. A request that never hints at the brand may not.

What I'd do differently

Reconcile the README and the CSS before packaging, not after. We shipped with the conflict and flagged it.

I'd also put the exact-bytes download at the top of the checklist. A casual preview is the easy way to corrupt a stylesheet.

The bottom line

A design system in a folder is documentation. Packaged as a skill, it's something Cowork applies without being asked.

Steps 1 to 4 are one-time work, and step 5 is the only one a teammate thinks about again. Write the brand down once, then stop re-explaining it.

If your team has a similar "the real answer lives in a doc/folder somewhere" problem — a style guide, a glossary, a set of house rules — this same pattern (SKILL.md + supporting files, zipped, installed) is worth copying. See About for how to contribute a follow-up post once you've tried it.
