Creating Your First Skill: A Beginner's Guide

Skill Deep Dive · 4 min read

Half the posts on this site mention a skill by name: design-system, agent-new-syndicated-segments, agent-pm. None of them explain what a skill is or how to build one from scratch.

If you've been installing other people's skills and wondering how they're made, this is that post.

What a skill actually is

A skill is a folder.

Inside it sits one required file, SKILL.md, plus whatever else you want to bundle: reference docs, scripts, templates. SKILL.md is a plain markdown file with a small YAML header on top. Nothing about it requires special tooling.

Anthropic's definition: Agent Skills are modular capabilities that extend Claude's functionality. Each one packages instructions, metadata, and optional resources that Claude uses automatically when relevant.

Why not just re-explain things in your prompt? A skill loads on demand and removes the need to repeat the same guidance across conversations. Write the instructions once, install the skill, and every future request that matches its description pulls them in. No "remember how we do this" reminder needed.

Progressive disclosure: what separates a skill from a saved prompt

Beginners usually skip this part. It's the part that explains why skills scale where a giant system prompt doesn't.

Skill content loads in three stages, and Claude only pays the token cost for what it actually needs:

The description field does real work here. It's the only thing Claude sees before deciding whether your skill is relevant.

Front-load concrete "use this when..." trigger phrases. A vague description means your skill either never fires or fires on the wrong requests.

Anatomy of a SKILL.md

Two frontmatter fields are required.

name: lowercase letters, numbers, hyphens only, max 64 characters, can't contain "anthropic" or "claude".

description: max 1,024 characters, can't be empty. It's the field that decides whether your skill triggers.

Below the header, the body is plain markdown instructions, written the way you'd brief a new hire:

---
name: weekly-metrics-digest
description: Pull last week's key product metrics into a short digest. Use when the user asks for "weekly numbers", "metrics recap", or "how did we do last week".
---

# Weekly Metrics Digest
1. Pull signups, activation rate, and churn for the last 7 days.
2. Compare against the prior 7 days, call out any move greater than 10%.
3. Write 3-5 sentences, ending with one recommended action.

That's already a complete, installable skill. No scripts or bundled files required.

Reach for Level 3 resources only once instructions alone get unwieldy, or when you need something deterministic, like a script that formats a spreadsheet the same way every time.

Building one, step by step

  1. Start from a real, narrow problem. "Summarize meetings" is too broad, because Cowork already does that unprompted. "Turn our Monday standup notes into the yesterday/today/blockers format our CPO expects" is narrow enough to be worth packaging.
  2. Draft and test it. Use the skill-creator skill (also installed on our team) to scaffold the frontmatter and check your description against the rules above. Then paste the draft into a real conversation and try the exact prompts teammates would use. If it doesn't trigger, the description is almost always the culprit.
  3. Package and install. Zip the skill's folder so the zip contains the wrapping folder itself (matching name:) with SKILL.md inside it, not a flat dump of loose files. Then upload the .skill file under Settings → Capabilities → Skills. From then on, matching requests trigger it automatically.

Where this breaks

A vague description is a skill that never fires. When a new skill doesn't trigger, read the description first.

Instructions alone get unwieldy. Past that point, move detail into Level 3 files, or into a script when the task has to run the same way every time.

Installing a skill is running someone else's instructions. A skill can direct Claude to run code and access files. Install skills only from people or sources you trust, the way you'd treat any other software on a work machine.

The bottom line

A skill is a folder with one required file and a description that decides when it loads. Everything else is writing down, once, what you'd otherwise keep re-explaining.

Start narrow, test with the prompts your teammates would really use, and fix the description first. Write it down once, then stop re-explaining.
